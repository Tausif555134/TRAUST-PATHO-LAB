## 🛡️ Security Architecture & Audit Report

A full backend security architecture was audited, hardened, and verified:

1. **SQL Injection Protection (100% Parameterized Queries)**:
   - Built on native `node:sqlite` (`DatabaseSync`).
   - Every query uses prepared statements (`db.prepare(...)`) with parameter bindings (`?`).
   - Untrusted inputs are never interpolated or concatenated into SQL statements.
   - Tested against SQLi payloads (`' OR '1'='1`, `'; DROP TABLE tests; --`, `CBC' UNION SELECT ...`, `admin'--`). All sanitized and neutralized.

2. **CSRF Protection (Double-Submit Token & Origin Validation)**:
   - State-changing mutations (`POST`, `PUT`, `DELETE`) require a cryptographically random 64-character hex CSRF token issued via `GET /api/csrf-token`.
   - Incoming mutations must pass `x-csrf-token` header matching and origin whitelist checks against trusted domains (`localhost`, `127.0.0.1`).
   - Cross-origin attacks with spoofed or untrusted origins are terminated with `HTTP 403 Forbidden`.

3. **Rate Limiting (Sliding Window Algorithm)**:
   - Login & OTP requests: Maximum 5 requests per 15 minutes.
   - Booking submissions: Maximum 10 requests per 15 minutes.
   - General API endpoints: Maximum 150 requests per 15 minutes.
   - Threshold violations return `HTTP 429 Too Many Requests` with a compliant `Retry-After` header.

4. **OWASP Security Headers**:
   - `Content-Security-Policy: default-src 'self'; ...`
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY`
   - `Strict-Transport-Security: max-age=31536000; includeSubDomains`
   - `Referrer-Policy: strict-origin-when-cross-origin`

5. **Role-Based Authorization & Price Management**:
   - Administrative price edits (`PUT /api/tests/:id/price`) require HMAC-SHA256 signed bearer authorization tokens.
   - Unauthenticated attempts return `HTTP 401 Unauthorized`.
   - Input bounds checking strictly validates `price > 0 && price <= 100000`.
